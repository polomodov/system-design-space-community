# Retry storm, Circuit Breaker, идемпотентность и Outbox

Стенд на `postgres:17.5-alpine3.21` воспроизводит отказ downstream без внешних сервисов: транзакционный Outbox сохраняет событие, но немедленные retry усиливают нагрузку, а at-least-once redelivery дублирует эффект.

## Прогноз

До отказа оцените число попыток при 12 немедленных retry и решите, какой механизм защищает нагрузку, а какой — бизнес-эффект. Backoff/Circuit Breaker и idempotency решают разные задачи.

## Запуск и healthy-check

```sh
./scripts/start.sh
./scripts/check.sh healthy
```

Order и Outbox event должны появиться в одной транзакции, попыток доставки ещё нет.

## Инъекция отказа и проверка

```sh
./scripts/inject-failure.sh
./scripts/check.sh failure
```

Наивный воркер делает попытки сам: пока зависимость молчит, он повторяет запрос немедленно и без бюджета, а после восстановления брокер доставляет то же событие второй раз. Ни количество попыток, ни дубль эффекта здесь никем не вписаны — проверка смотрит на то, что произошло.

## Решение и разбор

```sh
./scripts/apply-solution.sh
./scripts/check.sh solution
```

Изучите `solution/apply.sql`. Оба механизма отказывают в работе на уровне СУБД, а не описаны словами: триггер `BEFORE INSERT` поднимает исключение, пока размыкатель разомкнут, и именно он останавливает лавину — воркер не решает прекратить, его прекращают. Дубликат снимает первичный ключ таблицы `inbox`: повторная доставка получает `false` от `ON CONFLICT DO NOTHING`, и эффект не применяется. Переходы `closed → open → half-open → closed` пишет сам триггер в `circuit_transitions`.

Outbox обеспечивает атомарность публикации с изменением домена; Inbox обеспечивает идемпотентное потребление. Уберите триггер — и проверка `breaker-bounds-storm` упадёт; уберите первичный ключ — упадёт `duplicates-suppressed`.

## Безопасный reset

```sh
./scripts/reset.sh
```

Команда удаляет только именованные ресурсы проекта `sds-retry-storm-outbox` через его явный compose-файл. Глобальный cleanup не выполняется.
